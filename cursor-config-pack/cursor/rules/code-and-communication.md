When writing code:

1. Minimize scope — simplest correct diff, no unrelated changes
2. Avoid over-engineering — no unnecessary abstractions or error handling
3. Use existing conventions — match naming, types, imports, documentation level
4. Comments — only for non-obvious business logic
5. Tests — only when requested or meaningful coverage

When communicating:
- Code citations: ```startLine:endLine:filepath format
- Markdown links for URLs and paths
- Clear prose, proportional to task complexity
- Avoid excessive bolding/backticks

When citing code from the codebase, use code citation blocks with startLine:endLine:filepath format.
